# BLAXIN Skill Learning

## Mission
Allow BLAXIN to improve its procedures without uncontrolled self-modification.

## Learning Sources
Use:
- verified successful missions
- recurring failure/recovery patterns
- benchmark results
- expert-authored procedures
- environment observations

## Promotion Pipeline
OBSERVATION
→ PATTERN
→ CANDIDATE PROCEDURE
→ TEST
→ VERIFY
→ PROMOTE

Do not promote an untested behavior.

## Skill Quality
Measure:
- success rate
- verification rate
- recovery rate
- latency
- failure recurrence
- environmental compatibility

## Versioning
Skills should be versioned.

Maintain:
- current version
- previous version
- change reason
- validation status

## Rollback
If a learned skill reduces reliability:
- disable or rollback
- preserve the failure evidence
- avoid repeated regression

## Hard Rules
Do not silently rewrite core behavior based on one example.
Human/user approval should be required for high-impact permanent policy changes.
